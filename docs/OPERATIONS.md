# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 换月交接

1. 先签发基线批次（如可签发样例），其结论成为后续批次的旧依据。
2. 上游快照定义晚到时照常执行批次：引用链没变化的对象沿用已签发结论进入闭合单，身份不明或引用变化的对象被隔离，整批标记阻断并挡住签发。
3. 收到补发材料后重新执行：已签发结论不重复生成，只补齐受影响对象；闭合单无对账差异即可签发。
4. 源对象、快照定义和隔离项任一对不上时，闭合单保留对账差异和上一版结论，阻断批次在历史列表中以「阻断」标出。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
